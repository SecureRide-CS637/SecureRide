# SecureRide: Detecting Safety-Threatening E-Scooter Behavior from Battery Telemetry

An academic re-implementation and evaluation of **SecureRide** (Kim et al., ACM TECS / EMSOFT 2025).

SecureRide uses internal battery telemetry—voltage, current, and remaining capacity—as a side channel to detect potentially unsafe e-scooter behavior without relying on IMUs or GPS.

The project investigates two safety violations:

- **Speeding:** Riding above 20 km/h.

- **Illegal sidewalk riding:** Detecting rougher surfaces through increased battery-voltage fluctuations.

The detection system uses a lightweight ResNet-1D CNN, a stacked GRU, and scikit-learn baselines. A dual-mode detector combines a fast model for preliminary decisions with a longer-window model for more reliable confirmation.

This repository provides a physics-inspired synthetic data generator, model training and evaluation scripts, inference utilities, and additional experiments for class imbalance and temporal smoothing.

---

## 1. Overview

The project uses **synthetic battery telemetry generated by a physics-inspired scooter simulator**.

| Component | Description |
|---|---|
| Dataset | 36 hours of simulated telemetry at 5 Hz |
| Input features | Voltage, current, remaining capacity |
| Detection tasks | Speeding and sidewalk riding |
| Deep learning models | ResNet-1D CNN and GRU |
| Classical baseline | Scikit-learn |
| Training framework | PyTorch, with a scikit-learn alternative |
| Detection strategy | Dual-mode quick and accurate models |
| Data generation | `gen_dataset.py` |
| Model training | `train.py` |
| Inference | `predict_sample.py` |
| Evaluation | Metrics, plots, tests, and dual-mode experiments |

**Important:** The synthetic dataset and trained models are not included in the repository by default. Generate the data and train the required models before running the corresponding experiments.

## 3. Installation

Python 3.11 is recommended. Python 3.10 also works. The scikit-learn implementation can also run on Python 3.12 with compatible dependencies.

### Linux and macOS

```bash
git clone https://github.com/SecureRide-CS637/SecureRide.git
cd SecureRide
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### Windows PowerShell

```powershell
git clone https://github.com/SecureRide-CS637/SecureRide.git
cd SecureRide
py -3.11 -m venv .venv
Set-ExecutionPolicy -Scope Process Bypass
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

If script activation is blocked, run the execution-policy command in the same PowerShell session before activating the environment.

For Windows Command Prompt, activate the environment using:

```cmd
.venv\Scripts\activate.bat
```

### Lightweight installation without PyTorch

If you only want to run the scikit-learn experiments, install the required packages directly:

```bash
pip install numpy pandas scikit-learn matplotlib joblib scipy
```

PyTorch is required for the CNN and GRU implementations and for the associated model-training tests.

## 4. Quick Start

The following workflow generates the dataset, trains a baseline model, performs inference, and evaluates the dual-mode detector.

### Step 1: Generate synthetic telemetry

```bash
python gen_dataset.py
```

This generates:

- `data/trips.csv`

- `data/trips_meta.csv`

The simulator produces telemetry and associated labels for the supported detection tasks.

### Step 2: Build sliding windows

```bash
python secureride_data.py build
```

This creates windowed samples and normalization statistics, including:

- `data/secureride_windows.npz`

- `data/norm_stats.json`

- `data/window_counts.csv`

### Step 3: Check the simulated physical characteristics

```bash
python calibration_plots.py --root data --out results
```

The calibration experiment checks the simulated relationship between surface roughness and voltage jitter. The expected sidewalk-to-road jitter ratio is approximately 2.33× under the configured simulator assumptions.

### Step 4: Train the scikit-learn baseline

```bash
python train.py --backend sklearn --tasks sidewalk speeding --lengths 5 10 20 --hls 1 --max-train 10000 --max-eval 10000
```

This trains models for both tasks with window lengths of 5, 10, and 20 samples.

Typical outputs include model files in `models/` and evaluation metrics in `results/`.

### Step 5: Run inference

```bash
python predict_sample.py --input sample_sidewalk_illegal.csv --task sidewalk --model sklearn
```

The selected model must already have been trained. The `sklearn` keyword resolves to a saved model for the requested task and configuration.

### Step 6: Evaluate the dual-mode detector

```bash
python dualmode.py --task sidewalk --backend sklearn
```

The dual-mode experiment requires compatible trained quick and accurate models. Train the corresponding configurations before running it.

### Step 7: Run the tests

```bash
python -m unittest test_secureride test_contributions
```

Run the data-generation and window-building steps before executing the tests.

Without PyTorch, two tests in `test_secureride.py` that require deep learning will fail. The remaining tests can be run using the lightweight dependency installation.

## 5. Training and Model Evaluation

### 5.1 ResNet-1D CNN

The CNN is the primary deep learning architecture. It learns temporal patterns in battery telemetry to classify safety violations.

```bash
python train.py --backend torch --arch cnn --tasks speeding sidewalk --lengths 5 10 20 --hls 1 2 --max-train 4000 --max-eval 3000 --epochs 15
```

### 5.2 Stacked GRU

The GRU provides a recurrent neural network baseline for learning temporal dependencies in telemetry sequences.

```bash
python train.py --backend torch --arch gru --tasks speeding sidewalk --lengths 5 10 20 --hls 1 2 --max-train 4000 --max-eval 3000 --epochs 15
```

### 5.3 Scikit-learn baseline

The scikit-learn implementation provides a lightweight alternative for comparison and experimentation.

```bash
python train.py --backend sklearn --tasks speeding sidewalk --lengths 5 10 20 30 --hls 1 2 3 --max-train 15000 --max-eval 10000
```

### Useful training options

- `--epochs`: Number of training epochs.

- `--batch`: Batch size.

- `--seed`: Random seed.

- `--no-augment`: Disables training-data augmentation.

- `--l2 0.01`: Sets the regularization value used in the paper's configuration.

Training produces model files and evaluation artifacts, including:

```text
results/metrics_<backend>.csv
results/accuracy_<backend>.csv
results/fig5_accuracy_<backend>.png
models/
```

The exact output files depend on the selected backend and training configuration.

## 6. Prediction on Telemetry CSV Files

The inference script accepts telemetry CSV files with the following input columns:

| Column | Description |
|---|---|
| `voltage` | Battery voltage in volts |
| `current` | Battery current in amperes |
| `capacity` | Remaining battery capacity in mAh |

Use the following commands after training the relevant models.

### Speeding detection

```bash
python predict_sample.py --input sample_speeding_illegal.csv --task speeding --model models/speeding_L10_HL2.pt
```

### Sidewalk detection

```bash
python predict_sample.py --input sample_sidewalk_legal.csv --task sidewalk --model models/sidewalk_L10_HL2.pt
```

The `--model` argument accepts either an explicit model path or a supported keyword such as `cnn`, `gru`, or `sklearn`.

Keyword-based resolution requires the corresponding model to have been trained and saved.

To save window-level predictions:

```bash
python predict_sample.py --input sample_sidewalk_illegal.csv --task sidewalk --model sklearn --output preds.csv
```

To regenerate the sample CSV files from held-out simulated trips:

```bash
python make_samples.py
```

This step requires the generated dataset.

## 7. Dual-Mode Detection

The dual-mode detector implements the quick/accurate decision strategy.

The quick model uses a shorter observation window to produce an initial prediction. The accurate model uses a longer observation window to confirm or refine the decision.

This approach explores the trade-off between detection latency and prediction reliability.

### Run the detector

For CNN models:

```bash
python dualmode.py --task sidewalk --backend torch
python dualmode.py --task speeding --backend torch
```

For scikit-learn models:

```bash
python dualmode.py --task sidewalk --backend sklearn
python dualmode.py --task speeding --backend sklearn
```

The corresponding training runs must be completed first.

### Available options

- `--taus`: Threshold values for the detector.

- `--alphas`: Confidence or decision parameters.

- `--use-history`: Enables historical information where supported.

- `--smooth-n`: Configures temporal smoothing.

- `--hl-max-accurate`: Sets the maximum history length for accurate-model selection.

For example:

```bash
python dualmode.py --task sidewalk --backend sklearn --taus 1 1.5 2 --alphas 0.9 0.95 0.99
```

Evaluate detection performance alongside latency and false-alarm behavior rather than relying on accuracy alone.

## 8. Additional Experiments

### 8.1 Class imbalance

Real-world safety violations may be relatively rare. The imbalance experiment studies how different illegal-class prevalences and class-weighting strategies affect classification performance.

Example using PyTorch:

```bash
python imbalance.py --backend torch --task sidewalk --L 10 --hl 2 --prevalences 0.5 0.05 0.01 --weights none balanced --seeds 3
```

Lightweight scikit-learn version:

```bash
python imbalance.py --backend sklearn --task sidewalk --L 10 --hl 1 --prevalences 0.5 0.05 0.01 --weights none balanced --seeds 1
```

The experiment reports metrics such as precision, recall, F1-score, and false-positive rate.

Outputs include CSV summaries and plots under `results/`.

### 8.2 Temporal smoothing

Temporal smoothing applies majority voting over recent predictions to investigate the relationship between prediction stability, false alarms, and detection delay.

Example using scikit-learn models:

```bash
python smoothing.py --backend sklearn --task sidewalk --ns 1 3 5 7 --acc-hl 1
```

For PyTorch models trained with both history lengths:

```bash
python smoothing.py --backend torch --task sidewalk --ns 1 3 5 7
```

The required quick and accurate models must exist before running the experiment.

Compare precision, recall, F1-score, false-alarm rate, and detection delay when choosing a smoothing window.

### 8.3 Model comparison

Use the comparison script to visualize the relative performance of the CNN, GRU, and scikit-learn baselines.

```bash
python plot_comparison.py
```

Run the required training experiments first so that the corresponding result files are available.

## 9. Expected Results

### Example scikit-learn results

The following values are illustrative results from a verified synthetic-data run. Accuracy is measured on the held-out test split.

| Task | Window length 5 | Window length 10 | Window length 20 |
|---|---:|---:|---:|
| Speeding detection | 79.3% | 81.8% | 86.2% |

These results suggest that longer temporal windows can improve classification under the simulator's assumptions.

Exact values vary with the random seed, training configuration, augmentation settings, and dataset generation parameters. Re-run the experiments to obtain results for your own configuration.

Do not interpret these synthetic-data results as evidence of equivalent performance on real scooters.

## 10. Troubleshooting

| Error | Cause and solution |
|---|---|
| `Could not resolve model 'cnn' for task ...` | Train the corresponding task and backend first, or supply an explicit model path. |
| `Accuracy table not found: results/metrics_torch.csv` | Run `train.py` with `--backend torch` before evaluating the dual-mode detector. |
| `No model found for stem ...` | The requested window length or history length does not match the trained models. Train the required configuration or adjust the script options. |
| Most tests in `test_secureride.py` fail | Generate the dataset and build the sliding windows before running tests. |
| `ModuleNotFoundError: No module named 'torch'` | Install PyTorch or use the scikit-learn backend. |
| PowerShell reports that script execution is disabled | Run `Set-ExecutionPolicy -Scope Process Bypass` and activate the virtual environment again. |
| `python3: command not found` on Windows | Use `python` or `py -3.11`. |
| Missing model files | Run the corresponding training command and verify that the expected files exist under `models/`. |
| Incompatible dependency versions | Create a fresh virtual environment and reinstall the required packages. |
